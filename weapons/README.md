# Оружейная — 8 стволов (оптимизированная сборка)

Автономные страницы-«оружейные»: процедурная модель ствола со съёмными модулями, тир, стрельба,
оптика с картинкой в прицеле, фонари, ночь. Каждая страница — один HTML без ассетов (three.js r166 с CDN).

| Страница | Ствол |
|---|---|
| `dist/akm.html` | АКМ |
| `dist/ak74_modular.html` | АК-74М |
| `dist/m416.html` | HK416 / M416 |
| `dist/scar-h.html` | FN SCAR-H |
| `dist/glock18c.html` | Glock 18C |
| `dist/mp5a3.html` | HK MP5A3 |
| `dist/remington870.html` | Remington 870 |
| `dist/svd.html` | СВД |

## Устройство

Все восемь страниц собраны из одного движка — отличаются только файлом ствола и одним из двух
вариантов аудио. Поэтому исходники лежат один раз, а страницы собираются:

```
src/shell.html       HTML/CSS оболочка (общая)
src/prelude.js       служебный код бандла
src/engine/*.js      движок: сцена и пост-обработка, материалы, геометрия, модули, FX, баллистика, UI, PiP
src/weapons/*.js     описания стволов и их деталей
src/entries/*.js     точка входа каждой страницы
src/manifest.json    из каких секций и в каком порядке собирается каждая страница
build.mjs            сборщик: node build.mjs → dist/*.html
```

Исходники восстановлены из присланных бандлов без изменений: сборка из первого коммита байт-в-байт
совпадает с оригинальными файлами.

```bash
cd weapons
node build.mjs            # dist/*.html
npm install               # только для тестов (playwright)
npx playwright install chromium
node bench/bench.mjs      # замеры производительности
node bench/visual.mjs --a <папка с исходной сборкой> --b dist   # попиксельное сравнение картинки
```

## Что оптимизировано

Цель — убрать лаги и фризы на слабых ПК, **не меняя картинку**. Всё, что ниже, либо даёт тот же
результат по пикселям (проверено попиксельно, см. «Тесты»), либо переносит работу из кадра в простой.

1. **Пост-обработка без лишних полноэкранных проходов** (`src/engine/scene.js`).
   Раньше GTAO копировал весь кадр во второй буфер и отдельным проходом домножал его на AO, затем
   bloom ещё одним проходом дорисовывал свечение. Это три лишних чтения/записи HDR-кадра, причём в
   MSAA-буфер 4× (буферы композитора менялись ролями каждый кадр, поэтому MSAA держали на обоих).
   Теперь AO и свечение применяются прямо в финальном OutputPass (AO ещё и на входе bloom) по той же
   формуле и с той же выборкой текстур. В полном разрешении остался один проход, MSAA — только у
   буфера сцены, второй буфер на GPU не выделяется. Для слабой встроенной графики, которая упирается
   в пропускную способность памяти, это главная экономия на каждом кадре.
2. **Прогрев шейдеров в фоне** (`src/engine/app.js`). Раньше при загрузке компилировались только
   материалы модулей, стоящих на оружии. Первая установка прицела, фонаря или деревянного приклада,
   включение второго фонаря (меняется набор источников света у *всех* материалов), размытый диоптр при
   прицеливании — всё это компилировало шейдеры прямо в кадре и давало фриз от десятков миллисекунд до
   секунд. Теперь после загрузки в фоне (`compileAsync`, параллельная компиляция) готовятся все
   материалы библиотеки, их полупрозрачные варианты, служебные материалы (нормали GTAO, глубина теней,
   инстансы гильз), марка сетки и картинка в оптике — в обоих вариантах освещения. Экран загрузки из-за
   этого дольше не висит.
3. **Предсборка модулей в простое** (`src/engine/app.js`, `src/engine/ui.js`). Процедурная сборка
   модуля занимает 5–400 мс главного потока (большие прицелы — дольше всех) и раньше шла в момент
   клика. Теперь, когда игрок открывает список слота, его варианты собираются заранее, по одному за
   простой и только пока кадры не рисуются; модуль под курсором — первым. Клик берёт готовую модель из
   кэша. Всё сразу не собирается (это ~140 МБ и секунды CPU): держится ограниченное число заготовок,
   лишние выбрасываются.
4. **Исправлен баг теней при оптике** (`src/engine/pip.js`). Рендер картинки в прицеле (без оружия)
   забирал флаг обновления карт теней, и в основном кадре ствол терял собственную тень, пока стоит
   оптический прицел (у СВД — всегда). Теперь тени обновляет основной кадр. Картинка стала правильнее,
   а не беднее: геометрии в теневом проходе стало больше ровно на ствол.

Что было в движке и осталось: рендер по требованию (статичная сцена не перерисовывается),
автоподбор качества по видеокарте и времени кадра, динамическое разрешение в движении с полным
разрешением в покое, аудио, синтезируемое в простое.

## Тесты

Рендер для тестов — headless Chromium на SwiftShader, то есть программная растеризация на CPU.
Это заведомо «самый слабый ПК»: на нём видна любая лишняя попиксельная или геометрическая работа,
но абсолютные миллисекунды в десятки раз больше, чем на реальной видеокарте. Поэтому смотреть
нужно на относительную разницу. Исходная и оптимизированная сборки гонялись поочерёдно, ствол за
стволом, на одной машине.

- `bench/visual.mjs` — попиксельное сравнение: фиксированные время и `Math.random`, одинаковые шаги
  симуляции, кадр читается прямо из GL. Сценарии: день, очередь (вспышка, дым, гильзы), ночь с фонарём.
- `bench/bench.mjs` — стоимость кадра по сценариям при фиксированном DPR, «первые разы» (кадр сразу
  после события и число шейдеров, скомпилированных в этом кадре), смена модулей, draw calls.
- `bench/swaps.mjs` — смена модулей так, как это делает игрок: открыл слот, навёл курсор, кликнул.
- `bench/report.mjs` — сводные таблицы из JSON-результатов.

### Картинка

Все 8 стволов × 3 сценария (день, очередь, ночь с фонарём), 480×270: **0% пикселей с отличием больше
2/255, максимум 1/255** — это округление (`bench/results/visual.txt`). Исключение — сценарии, где
стоит оптика: там теперь правильно рисуется тень ствола (п. 4).

### Производительность

Полные таблицы: `bench/results/REPORT.md` (8 стволов, «высокое» + 2 ствола на «низком», 640×360) и
`bench/results/REPORT-1080.md` (АКМ, 1920×1080). Сырые данные — рядом, в JSON.

| | было | стало |
|---|---|---|
| шейдеров, скомпилированных прямо в кадре (первый прицел, фонарь, второй фонарь…), сумма по всем прогонам | **71** | **0** |
| смена модуля по сценарию игрока, медиана по стволам | 9–33 мс | **2–6 мс** |
| смена модуля, худший случай по стволам | 32–169 мс | **2–61 мс** |
| стоимость кадра, 640×360, сумма всех сценариев | 62,9 с | **60,0 с (−5%)**, на «низком» до −12% |
| стоимость кадра, 1920×1080 (АКМ) | 46,0 с | **42,6 с (−7%)**, каждый сценарий −6…−8% |

Время загрузки на программном рендере в этой песочнице плавает от 20 до 120 с от запуска к запуску
даже у исходной сборки, поэтому как результат оно не приводится. Экран загрузки ждёт ту же работу,
что и раньше; прогрев шейдеров идёт уже после него.

### Как повторить

```bash
cd weapons && npm install && npx playwright install chromium
mkdir -p /tmp/base && for f in dist/*.html; do git show 3c8cf3d:weapons/$f > /tmp/base/$(basename $f); done   # исходная сборка
node bench/visual.mjs --a /tmp/base --b dist
node bench/bench.mjs --dir /tmp/base --out bench/results/base.json
node bench/bench.mjs --dir dist --out bench/results/new.json
node bench/swaps.mjs --dir dist
```
